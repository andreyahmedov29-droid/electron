# Self-update: первый запуск пошагово

Всё уже встроено в проект — сервер отдаёт версию, приложение проверяет и качает
APK из GitHub Release, CI публикует Release. Осталось один раз «вписать» ссылку
и версию, а затем проверить на устройстве.

---

## Шаг 1. Убедиться, что APK публикуется в GitHub Release

1. Откройте репозиторий → вкладка **Actions** → запустите **Build APK** (Run workflow).
2. Убедитесь, что шаг **«Опубликовать APK в GitHub Release»** прошёл зелёным.
3. Перейдите в репозиторий → вкладка **Releases** → должен появиться
   **«BIOTIME APK (latest)»** с файлом **`app-release.apk`**.

> Если шаге публикации нет Release — включите разрешение:
> Settings ▸ Actions ▸ Workflow permissions ▸ **Read and write permissions**.

## Шаг 2. Получить прямую ссылку на APK

Ссылка выглядит так:
```
https://github.com/<ваш_логин>/<имя_репозитория>/releases/download/biotime-apk-latest/app-release.apk
```

Например (замените на свои значения):
```
https://github.com/andreyahmedov29-droid/biotime-android/releases/download/biotime-apk-latest/app-release.apk
```

Проверьте, что по этой ссылке скачивается файл (вставьте её в браузер — должен
начаться download) прежде чем вписывать.

## Шаг 3. Задать версию и ссылку на сервере

Нужно передать приложению 4 значения. Самый надёжный вариант для этой платформы —
вписать их как значения по умолчанию прямо в [server.js](server.js), в эндпоинт
`/api/app/update-info` (значения подставляются из `process.env`, а при их отсутствии
берутся дефолты ниже).

| Переменная | Что вписать | Пример |
|---|---|---|
| `APP_UPDATE_VERSION_CODE` | целое число, **увеличивать** при каждом новом релизе | `2` |
| `APP_UPDATE_VERSION_NAME` | человекочитаемая версия | `1.0.1` |
| `APP_UPDATE_APK_URL` | прямая ссылка на `app-release.apk` (Шаг 2) | `https://...app-release.apk` |
| `APP_UPDATE_NOTES` | короткое описание изменений для диалога | `Исправлен трекинг` |

> Прямо сейчас в коде стоят дефолты `versionCode:1`, `versionName:"1.0.0"`,
> `apkUrl:""`. Пока `APP_UPDATE_APK_URL` пуст — приложение просто не предлагает
> обновление. Как только впишете ссылку и версию выше текущей — начнёт работать.

## Шаг 4. Задеплоить сервер

После правки [server.js](server.js) изменения попадают на сервер через кнопку
**«Деплой»** (или ключ VibeCode). Без деплоя сервер продолжит отдавать старую
версию (без ссылки).

## Шаг 5. Проверить на устройстве

1. Установите текущий APK (из прошлой сборки) на телефон водителя.
2. Откройте приложение — оно запросит `/api/app/update-info`.
3. Если вписана версия новее установленной и ссылка — появится диалог
   **«Доступно обновление»** с кнопкой **«Обновить»**.
4. Нажмите **«Обновить»**:
   - приложение скачает новый APK;
   - **первый раз** система откроет настройки «установка из неизвестных
     источников» — включите для этого приложения;
   - вернитесь и подтвердите установку → приложение перезапустится новой версией.

## Как понять, что всё работает

- Вкладка **Releases** репозитория содержит `app-release.apk`.
- По прямой ссылке (Шаг 2) скачивается файл.
- На телефоне появляется диалог обновления (Шаг 5.3).
- В `server.js` дефолт `apkUrl` не пустой.

## Частые проблемы

- **Диалог не появляется** → либо `apkUrl` пуст, либо `versionCode` на сервере
  не больше установленного в приложении, либо сервер не задеплоен. Проверьте все 4.
- **Не скачивается по ссылке** → репозиторий приватный и браузер без входа не
  видит Release; тогда ссылку нужно передавать с авторизацией или сделать
  Release публичным (это даёт прямой доступ).
- **Нет кнопки «Обновить»/Release** → не включено «Read and write permissions» (Шаг 1).
