# Развёртывание одним контейнером (заготовка для переезда на свой сервер)

Это отдельная папка `deploy/` для будущего переноса на собственный сервер.
Она **не влияет** на основное приложение и не раздаётся им как страницы — код
приложения не изменялся.

## Подготовка

1. На сервере установлен Docker (и Docker Compose V2).
2. Скопируйте проект в любую папку сервера (например `/opt/biotime`).
3. Перейдите в неё.

## Запуск

```bash
# из корня проекта (там лежит папка deploy/ и .dockerignore)
docker compose -f deploy/docker-compose.yml up -d --build
```

Готово: приложение поднято в контейнере и слушает `:3000`.
Проверка:
```bash
curl http://127.0.0.1:3000/api/health   # или просто откройте http://<сервер>:3000
```

## Настройка (один раз)

- **Данные** — лежат на томе `biotime_data` (`/data` внутри контейнера). Они
  переживают пересоздание контейнера. Чтобы сохранить текущую историю, перенесите
  файлы из вашей прежней `DATA_DIR` (db.json и др.) внутрь этого тома.
- **Переменные** — скопируйте `deploy/.env.example` в `deploy/.env` и заполните
  нужные (`PORT`, `DATA_DIR`, ключи 1С/карт/портала — по необходимости).
- **Доступ из интернета** — обязательно за обратным прокси с HTTPS (nginx/Caddy) и
  со слоем авторизации, т.к. на своём сервере нет шлюза VibeCode.
