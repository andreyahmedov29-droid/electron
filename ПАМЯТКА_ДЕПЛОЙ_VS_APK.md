# Памятка: деплой vs пересборка APK

Когда вы вносите изменения в BIOTIME, важно понимать, **куда именно** они
попадают. Проект двухслойный:

## Два слоя приложения

1. **Веб-приложение BIOTIME** — `app.js`, `server.js`, `index.html`, CSS.
   Живёт на сервере (`vibecode`).
2. **Android-обёртка** — папка `android/` (WebView + фоновый трекер).
   Именно из неё собирается APK.

APK — это «оболочка», которая **открывает веб-приложение по адресу**, а не
хранит его внутри. Поэтому:

| Что изменили | Пересобирать APK? | Что сделать |
|---|---|---|
| Логику/UI веб-приложения (`app.js`, `server.js`, HTML) | ❌ **Нет** | Задеплоить на сервер («Деплой» / ключ VibeCode) |
| Фоновый трекинг, сервис, права, иконку, название (папка `android/`) | ✅ **Да** | Собрать APK в GitHub Actions и переустановить водителям |

---

## Случай 1 — изменили веб-приложение

- **APK пересобирать НЕ нужно.**
- Изменения попадают на сервер через «Деплой» (или ключ VibeCode).
- Водители видят их сразу: обновилась страница в приложении → новые кнопки/логика
  доступны **без пересборки и переустановки APK**.

## Случай 2 — изменили нативную обёртку

- **APK пересобирать нужно** (уже установленные APK старые версии не обновятся сами).
- Собрать: вкладка **Actions** → **Build APK** → **Run workflow**.
- Скачать `biotime-apk` → раздать водителям `app-release.apk` → установить заново.

---

## Куда выносить изменения, чтобы реже пересобирать

Старайтесь делать правки в **веб-части** — они доходят до водителей мгновенно
и без переустановки:

- ✅ Кнопки, формы, отчёты, карта, логика, тексты — это веб-часть → деплой.
- ⚠️ Только когда правка про сам телефон — фоновый трекер, разрешения,
  батарея, уведомления, иконка, название приложения — это папка `android/` → APK.

---

## Мини-процесс правки

1. Меняете код (веб или натив).
2. Если **веб** → «Деплой» / ключ → водители видят сразу.
3. Если **натив** (`android/`) → GitHub Actions → собрать APK → раздать заново.

Разделяйте: **«логика/интерфейс» → деплой, «сам телефон» → APK**.
