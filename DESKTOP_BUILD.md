# BIOTIME — desktop-приложение для Windows (Electron)

Веб-версия BIOTIME остаётся как есть и работает по-прежнему.
Этот проект добавляет к ней **отдельное Windows-приложение** на Electron:
оно открывает веб-версию в собственном окне (иконка, свой `.exe`) и проходится
через шлюз платформы **access-токеном** — данные/табель остаются общими, как в вебе.

## Схема работы (режим A — по умолчанию)

- Адрес веб-версии: `https://app-2660de1a180b.vibecode.bitrix24.tech`.
- Десктоп открывает этот адрес в своём окне. По умолчанию **никакой общий токен
  не подставляется**: окно ведёт себя как обычный браузер, шлюз проводит
  **личный вход каждого пользователя** под его собственной учёткой, и его сессия
  сохраняется на его машине. Так каждый водитель попадает к себе под своим именем.
- Запасной режим (один общий токен на всех) включается только явно — полем
  `"useSharedToken": true` в `biotime.config.json` либо `BIOTIME_USE_SHARED_TOKEN=1`:
  тогда окно добавляет `Authorization: Bearer <access-token>` ко всем запросам
  (иначе шлюз вернёт `401`).
- Данные, табель, список сотрудников — всё то же, что в веб-версии (общее).
- Свой локальный сервер в режиме A не запускается.

Если адрес/токен не заданы — приложение переходит в локальный автономный режим B
(поднимает собственную копию `server.js`, данные в `%APPDATA%\BIOTIME\data`).

## Что внутри

- `electron/main.js` — главный процесс: запускает `server.js`, ждёт готовности
  и открывает окно с интерфейсом `http://localhost:3123`.
- `package.json` — скрипты `desktop` (запуск в dev) и `desktop:pack` (сборка `.exe`),
  конфиг electron-builder (NSIS-установщик + portable).
- Локальные данные (БД `db.json`, треки, бэкапы) хранятся в папке приложения
  (`%APPDATA%\BIOTIME\data`), а не в `/data` — на Windows сервер пишет туда,
  где есть права.

## Как собрать `.exe` (на своей Windows-машине с интернетом)

1. Откройте папку проекта в терминале (PowerShell/CMD).
2. Установите зависимости (нужен доступ к npm-реестру):

   ```powershell
   npm install
   ```

3. Соберите установщик и portable-версию:

   ```powershell
   npm run desktop:pack
   ```

4. Готовые файлы появятся в папке `dist/`:
   - `BIOTIME Setup 1.0.0.exe` — установщик (NSIS);
   - `BIOTIME 1.0.0.exe` — portable (носимая) версия.

## Быстрый запуск без установки (режим разработчика)

```powershell
npm install
npm run desktop
```

Откроется окно приложения, внутри работает локальный сервер BIOTIME.

## Важно

- Сборка Electron тянет пакеты из npm (electron ~100 МБ). Если `npm install`
  падает с `ENOTCACHED`/нет сети — на этой машине просто нет доступа к реестру,
  соберите `.exe` там, где интернет есть.
- `.env` (портальные ключи) в сборку **не включается** — это секреты. Локальное
  приложение работает автономно; синхронизация с порталом Битрикс24 останется
  дольше/потребует отдельной настройки доступа.
- Порт по умолчанию `3123`. Если занят — задайте свой:
  `$env:BIOTIME_PORT=4000; npm run desktop`.
- Название и иконка приложения задаются в `package.json` (`productName`, `appId`)
  и в `electron/main.js` (заголовок окна). При желании их легко поменять.

## Настройка доступа к веб-версии (access-токен)

Токен и адрес НЕ хранятся в коде/сборке. Их можно задать двумя способами:

**1. Конфиг-файл (для раздачи сотрудникам — удобнее).**
Создайте файл `biotime.config.json` в папке данных приложения
(`%APPDATA%\BIOTIME\biotime.config.json`):

```json
{
  "appUrl": "https://app-2660de1a180b.vibecode.bitrix24.tech",
  "accessToken": "vibe_app_local_<ВЫДАННЫЙ_ПЛАТФОРМОЙ_ТОКЕН>"
}
```

**2. Переменные окружения (для проверки).**
```powershell
$env:BIOTIME_APP_URL = "https://app-2660de1a180b.vibecode.bitrix24.tech"
$env:BIOTIME_ACCESS_TOKEN = "<ВЫДАННЫЙ_ПЛАТФОРМОЙ_ТОКЕН>"
npm run desktop
```

Актуальную пару «адрес + токен» для инстанса выдаёт платформа Вайкода
(эндпоинт выдачи access-токенов для приложения). Токен чувствителен — не
светите его в переписках и не кладите в git.

## Миграция на новый адрес инстанса (чек-лист для раздачи водителям)

После переноса веб-версии на новый адрес
`https://app-2660de1a180b.vibecode.bitrix24.tech` проверьте следующее:

1. **Код сборки** — новые адреса уже прописаны в `electron/main.js` (fallback),
   `MainActivity.kt` (Android) и Swift-обёртках (iOS). Собирайте новую версию из
   актуального кода.
2. **Уже установленные desktop-машины** — в `biotime.config.json`
   (`%APPDATA%\BIOTIME\biotime.config.json`) может остаться **старый** `appUrl`,
   который перекроет новый fallback в коде. На каждой такой машине:
   - либо удалите поле `"appUrl"` из файла (тогда применится новый адрес из кода);
   - либо замените значение на актуальное:
     `"appUrl": "https://app-2660de1a180b.vibecode.bitrix24.tech"`,
   и перезапустите приложение.
3. **Режим входа** — при переходе на личный вход без общего токена водителю
   достаточно один раз войти в свою учётку в окне приложения. Если для части
   машин нужно сохранить прежний общий токен — включите запасной режим
   (`useSharedToken: true`), не трогая остальной конфиг.
4. **Автообновление и ссылки** — `apkUrl` для Android и десктоп-обновления
   берутся из параметров/окружения, а не зашиты в код. После переезда направьте
   на сервер актуальный `apkUrl` на новый адрес (через `POST /api/app/update`
   или `APP_UPDATE_APK_URL`), чтобы кнопка «Скачать обновление» вела на новый
   инстанс.
