# Учёт пробок в оптимизации маршрута (TomTom)

Оптимизация «Построить оптимальный маршрут» в BIOTIME может учитывать
реальные пробки, если задан ключ TomTom. Без ключа маршрут строится по
дорогам (OSRM) или «по прямой» — всё продолжает работать.

## Как это устроено (порядок выбора сервиса в коде)

1. **TomTom (ключ)** — реальное время в пути **с учётом пробок**;
2. **OSRM** — реальные дороги, но без живых пробок;
3. **Гаверсинус** — «по прямой», если оба недоступны.

Эндпоинт: `POST /api/drivers/routes/optimize` в [server.js](server.js).

## Как получить ключ TomTom

1. Откройте https://developer.tomtom.com/ → **Register** (создайте аккаунт).
2. Подтвердите почту, войдите.
3. Раздел **My Apps** → **Add a new App** → имя (например `biotime`).
4. Внутри приложения **Add an API Key** → выберите продукт **Routing API**.
5. Скопируйте сгенерированный ключ.

> Free-аккаунта TomTom достаточно на старт (~2500 запросов/мес на Routing API).
> Для пары маршрутов в день этого хватает.

## Как подключить ключ

Значение ключа задаётся через переменную окружения `TOMMOM_KEY` на сервере.
В коде уже есть поддержка:

```
const TOMMOM_KEY = String(process.env.TOMMOM_KEY || "");
```

После деплоя с заполненным `TOMMOM_KEY` оптимизация начнёт использовать
TomTom (т.е. пробки). Без ключа — фолбэк на OSRM/гаверсинус, ничего не ломается.

## Проверка

1. С ключом: постройте маршрут на пару точек — порядок должен считаться по
   реальному времени (с пробками).
2. Без ключа: маршрут строится по дорогам (OSRM) — тоже работает, просто
   без учёта текущих пробок.

## Оговорки

- TomTom — глобальный сервис; покрытие **России хуже, чем у Яндекса**.
  В крупных городах более-менее ок, в небольших населённых пунктах может
  быть неточно. При необходимости рассмотрите Яндекс/Google (платные, но
  точнее по РФ).
- Пробки учитываются на момент построения маршрута; по ходу дня меняются,
  но порядок обычно остаётся разумным.
